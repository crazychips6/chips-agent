# 多模块新增的 Coding Path

当一个任务需要新增多个模块并串联时，按此路径推进。

## 推进顺序

```
核心零依赖模块 → 依赖方 → 组合根 wiring → 测试 → 修 bug → 文档
```

## 步骤说明

1. **先读相关代码** — 理解已有上下文和约束，不必全量通读
2. **从零依赖模块开始写** — 第一个模块不依赖项目其他模块，先实现它可独立验证
3. **写依赖方** — 集成上一步已就绪的核心模块
4. **写组合根 wiring** — 最后组装所有模块的汇合点（如 cli.py）
5. **测试** — 新模块写单元测试后，全量跑 `pytest -v` 确保不破坏已有功能
6. **修 bug** — 逐一修复失败测试
7. **更新进度 + 写 coding log**

## 原则

- 每次只保证一个模块可工作，不跳步
- 零依赖模块最先，降低验证成本
- wiring 最后做，因为它是所有模块的汇合点
- 测试覆盖边界（空数据、大内容、unicode、并发）
